# 需求拷问（design-grill）

把一个**还没想清楚的想法**，通过分轮提问，逼到「你能为每个选择辩护」为止。产出只在对话里，不写文件、不动代码。

> 来源：mattpocock/skills 的 `grill-me`，按本项目上下文改写。区别：本 skill 拷问完后**会显式接入**本项目的规范/ID 映射/skill 流程。

---

## 何时用 / 何时不用

| 用 | 不用 |
|----|------|
| 只有「我想加个 XXX」这种模糊念头 | 设计已明确，直接走 `port-content` 或对应系统 skill |
| 要做新机制/新系统，不确定边界 | 只是搬运既有内容且映射已定 |
| 面对分叉（自己设计 vs 搬旧内容、客制化类 vs 原版类） | 需求是 bug 修复或明确的重构 |

**触发时机**：在写 `document/rule/program/` 规范、登记 `ID映射表.md`、生成 SKILL 之前。**不**在 AI 已经写好的计划上叠加拷问。

---

## 核心原则

1. **无状态**：不读仓库、不写文件、不留 TODO，唯一产出是「你脑子里更清晰的想法」。
2. **分轮提问，每轮问「前沿」**：每轮只问**前置条件已确定**的问题，绝不问依赖未答问题的问题。后轮必须建立在前轮答案上。
3. **数轮数，不数问题数**：四轮问四十多个问题是正常的。一轮问两百个 = 范围太大，先让 agent 拆分成小块再逐个拷问。
4. **用户主导范围**：失败模式是「同意、同意、同意」，最后拿到一份 AI 写的、你只会点头的假计划。要主动反驳、指出范围漂移、该说「不知道」就说。
5. **结束条件：前沿为空**——每个分支都走过，没有沉默的假设。

---

## 项目特定拷问清单

按需挑问，**每轮只问当前可问的**：

- **性质**：完全新设计 / 搬运旧内容 / 废案复活？（决定是否登记 ID 映射）
- **ID 与命名**：新增还是重命名？语义化 snake_case？与既有 ID 冲突？工具/护甲材料是否一致？
- **载体**：方块 / 物品 / 工具 / 护甲 / 饰品 / 实体 / 维度 / 群系 / 地物 / 配方 / 进度？
- **实现路径**：客制化类还是原版类？Forge 事件驱动，还是确需 Mixin？（Mixin 永远是最后手段）
- **与既有系统的交互**：SAN / 融梦能量 / 技能 / 暗影难度 / 进度笔记 / 跨维度传送？
- **数据来源**：走 datagen 还是手动维护 JSON（如 Curio 槽位标签、粒子定义、sounds.json）？
- **平衡**：若涉及配方/数值，参照 `容器配方平衡系统.md` 的量级？
- **客户端**：是否需要渲染层 / 粒子 / 音效 / HUD / GeckoLib 动画？
- **服务端安全**：客户端专属与逻辑的分离点（`isClientSide()` 门控）？
- **存档与配置**：是否需要持久化（Capability / persistentData）？是否需要配置项或 gamerule？
- **收尾**：这次变更会触发 AGENTS.md §五 哪些「Definition of Done」条目？

---

## 不可拷问：必须做原型才知道

遇到下面这些，**立即停止拷问**，先做最小可验证原型（临时方块 / 命令 / 硬编码数值），用 `runClient` 看过之后再回来用一句话敲定：

- 数值手感（倍率、冷却、伤害、刷怪率）
- 渲染/动画/粒子观感、模型比例
- HUD / GUI 布局
- 游戏节奏与「爽不爽」

硬聊这些只会让 session 膨胀：AI 反复改写、你反复猜，范围随不确定性一起长大。

---

## 结束与接入

前沿清空后，**不要新开对话**——直接带着这份上下文交接：

| 成型的东西 | 落点 |
|-----------|------|
| 新/改的 ID | `document/design/ID映射表.md`，并跑 `tools` 刷新 `mapping.json` |
| 新机制 / 数值规则 | `document/rule/program/` 对应规范（配方平衡、暗影难度等） |
| 新搬运类型 / 流程变化 | `document/design/策划文档.md` §六 + `port-content` |
| 新领域速查 | 新建或更新 `.claude/skills/*/SKILL.md` |

然后再进入执行：搬运走 `port-content`，加实体走 `entity`，加维度走 `worldgen`，以此类推。

---

## 判好标准

- 你**反驳过**至少一次——全程零反驳的 session 说明本可以不做。
- 问题分几轮递进，后轮明显建立在前轮答案上。
- 你最后落在了一个**意料之外**的地方，因为某个问题逼出了一个你一直在暗中默认的决定。
- 你能向没在场的人**解释并辩护**每个选择。
