# 料理状态效果

> 权威规范：`pasterdream:cook`（原模组 `cook_buff`）效果的行为规则。实现见 `event/CookOverflowHandler.java`。

## 效果定位

- 注册 ID：`pasterdream:cook`，中文名「料理」（搬运自原模组 `cook_buff`，ID 已在 `ID映射表.md` 登记）。
- 保留原有属性加成：`SAN_VARIABILITY` +1.2（`ADDITION`），随等级线性放大。
- 在此基础上新增「可无条件进食 + 溢出转生命 / 黄心」机制（**全新设计**，非搬运）。

## 进食门控

原版 `Player.canEat` 在生存模式且饱食度满时只放行 `alwaysEat` 食物（`abilities.invulnerable || canAlwaysEat || needsFood`）。拥有 `cook` 效果时，通过 `mixin/PlayerCanEatMixin` 在 `Player.canEat` 的 `HEAD` 处以 `@Inject(cancellable = true)` 短路返回 `true`，使玩家**可无条件进食任意食物**（含普通食物；`CakeBlock` 走同一入口，蛋糕方块同样放行）。

- 用 `@Inject` 而非 `@Overwrite`，保留原方法体与其他模组的注入。

## 溢出机制

**触发条件**（全部满足才结算）：

1. 玩家在服务端进食结束（`LivingEntityUseItemEvent.Finish`）；
2. 食物可食用（`stack.getFoodProperties(player)` 非空）；是否 `alwaysEat` 不限，`cook` 已放行任意食物；
3. 进食前 `foodLevel == 20`；
4. 进食结束瞬间玩家身上已有 `cook` 效果。因 `finishUsingItem` 内先 `FoodData.eat` 再 `addEffect(cook)`，Finish 事件晚于效果应用，故**授予 cook 的那一口本身也算**。

**溢出量**（只算真正被浪费的部分，依据原版 `FoodData.eat`）：

- `postFood = min(preFood + nutrition, 20)`
- `postSat = min(preSat + nutrition * satMod * 2, postFood)`
- `溢出 = (preFood + nutrition - postFood) + (preSat + nutrition * satMod * 2 - postSat)`

**结算顺序**：

1. 先补生命：`healed = min(溢出, maxHealth - health)`，调用 `player.heal(healed)`；
2. 剩余 `溢出 - healed` 转为原版吸收（黄心）。

**黄心上限**：`上限 = (cook 等级 + 1) * 10`，即 cook I=20、II=30、III=40。

- 加法时钳总量：`current + min(剩余, max(0, 上限 - current))`；
- 永不降低已有吸收量；不单独追踪本效果贡献（其他来源如吸收药水可把总量顶超上限，不做拦截）；
- 上限**不**限制补生命。

**生命周期**：吸收同原版——受击消耗、不自然衰减；`cook` 效果结束或降级**不会**清除已获得的黄心。

## 实现路径

- 进食门控：`mixin/PlayerCanEatMixin`（`@Inject` 短路 `Player.canEat`）。
- 溢出结算：纯 Forge 事件，无 Mixin：
  - `LivingEntityUseItemEvent.Start` 记录进食前 `[foodLevel, saturation]`；
  - `LivingEntityUseItemEvent.Stop` 清理未完成的记录；
  - `LivingEntityUseItemEvent.Finish` 计算溢出并结算。
- HUD 复用原版吸收黄心，无自定义渲染。

> 注意：`CakeBlock` 进食不经过 `LivingEntityUseItemEvent`，故蛋糕方块被放行后不参与溢出结算。
