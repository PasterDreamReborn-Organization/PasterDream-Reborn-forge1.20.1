# 风之旅途「风向机制」搬运分析

> PasterDream Reborn — `wind_journey_world` 维度附带的**风向（顺风/逆风）游戏机制**搬运方案
> 原作源码位于 `NOT_MODIFY/reference/net/pasterdream/`（严禁修改），本文档为搬运分析。
> 关联文档：[[风之旅途维度搬运分析]]（维度代码已全部落地，本文档只补「风向」这一套玩法机制）。

---

## 〇、结论速览

风向机制**尚未搬运**。它是一套独立的玩法系统，与维度代码（群系/地物/结构）解耦，核心依赖三样东西：

1. 一个**游戏规则** `pasterdreamWindDirection`（0~7 表示 8 个方向）；
2. 三个**效果**：顺风 `tailwind_buff`、逆风 `deadwind_buff`、防风 `windproof_buff`；
3. 两个**tick 钩子**：世界 tick（每日换向 + 播报）与玩家 tick（按朝向判定顺风/逆风）。

另有两个**饰品**参与：风向标 `wind_vane`（查询当前风向）、风骑士旗帜 `wind_knight_flag`（把逆风当顺风）、纸飞机 `paper_plane`（增大风向影响）。

## 一、原作机制全景

### 1.1 核心数据流

```
[世界 tick]  WindDirectionPr0Procedure
    └─ 每 24000 tick（一昼夜）随机换向：dayTime % 24000 == 0
       └─ 写 gamerule pasterdreamWindDirection = 0~7
       └─ 播报风向文案 + 播放 wind_chime / breeze_wind + 羽毛粒子

[玩家 tick]  PlayerTotalTickUpdateProcedure（每 N tick，N = config PLAYER_TOTAL_TICK_UPDATE）
    └─ 若玩家没有 windproof_buff：
       ├─ WindDirectionPr1Procedure  → 顺风判定（顺风给 tailwind_buff）
       └─ WindDirectionPr2Procedure  → 逆风判定（逆风给 deadwind_buff；戴旗帜则给 tailwind_buff）
```

### 1.2 8 方向定义

风向值 0~7 依次对应 北/东北/东/东南/南/西南/西/西北 八个方向。

**方向语义**：`北风` 表示「风从北方吹来」→ 风吹向南方。顺风 = 玩家面向风的下游（被风推着走）；逆风 = 玩家面向风的上游（顶着风走）。

| 值 | 中文名 | 风吹向（下游） | 顺风 yaw 区间（Pr1） | 逆风 yaw 区间（Pr2） |
|----|--------|--------------|---------------------|---------------------|
| 0 | 北风 | 南 | `[-35, 35]` | `[145, 180] ∪ [-180, -145]` |
| 1 | 东北风 | 西南 | `[10, 70]` | `[-170, -100]` |
| 2 | 东风 | 西 | `[55, 125]` | `[-125, -55]` |
| 3 | 东南风 | 西北 | `[100, 170]` | `[-80, -10]` |
| 4 | 南风 | 北 | `[145, 180] ∪ [-180, -145]` | `[-35, 35]` |
| 5 | 西南风 | 东北 | `[-170, -100]` | `[10, 70]` |
| 6 | 西风 | 东 | `[-125, -55]` | `[55, 125]` |
| 7 | 西北风 | 东南 | `[-80, -10]` | `[100, 170]` |

> **yaw 约定**（Minecraft 标准）：`0°=南(+Z)`、`90°=西(-X)`、`180°/-180°=北(-Z)`、`-90°=东(+X)`。8 个区间各 45°，中心分别为 0/45/90/135/180/-135/-90/-45，完整覆盖 360°。
>
> Pr2 的 yaw 区间 = Pr1 的 yaw 区间按方向值 **+4（mod 8）** 平移，即「逆风方向 = 顺风方向的反方向」。这是理解 Pr2 的关键。

**⚠️ 原作文案矛盾（搬运注意）**：`WindDirectionPr0Procedure` 的换向公告文案是「风吹往**北方**」（值 0 时），而风向标 `WindVanePr0Procedure` 与效果逻辑都按「北风 = 从北吹来 = 吹往南」处理。即公告文案与实际物理方向相反（措辞问题）。搬运时以**代码行为**（yaw 判定表 + 效果）为准，公告文案可沿用原作文字或另行修正。

### 1.3 顺风 / 逆风 / 防风三效果

| 效果 | 类别 | 颜色 | 触发条件 | 属性修正（amplifier 0 / 1） |
|------|------|------|---------|------------------------------|
| `tailwind_buff`（顺风） | BENEFICIAL | `-7087682` | 面向风下游（Pr1）或戴旗帜逆风（Pr2） | 见下表 |
| `deadwind_buff`（逆风） | HARMFUL | `-1666709` | 面向风上游且未戴旗帜（Pr2） | 见下表 |
| `windproof_buff`（防风） | BENEFICIAL | `-4396554` | 由其他途径授予（本机制外） | 无，仅作「免疫风向」标记 |

**顺风（tailwind_buff）属性修正**（`TailwindBuffPr0Procedure`，addAttributeModifiers 时叠加；apply 时先移除逆风）：

| 属性 | amplifier=0 | amplifier=1 | 操作 | UUID |
|------|-------------|-------------|------|------|
| `MOVEMENT_SPEED` | +0.03 | +0.04 | ADDITION | `a70291bb-c451-4b26-b160-55f7b12c32ed` |
| `teleportationrange` | +1 | +1.5 | ADDITION | `78c6cb5b-3f93-4e1c-a22f-6a3f2a3ed1ff` |
| `teleportationcd` | ×0.7 | ×0.6 | MULTIPLY_BASE | `5aa8de78-2c53-4e9a-9205-87e71fa62ea1` |

**逆风（deadwind_buff）属性修正**（`DeadwindBuffPr0Procedure`；apply 时先移除顺风）：

| 属性 | amplifier=0 | amplifier=1 | 操作 | UUID |
|------|-------------|-------------|------|------|
| `MOVEMENT_SPEED` | -0.02 | -0.03 | ADDITION | `ec261013-84a4-41b1-99ca-89754fd5f1e8` |
| `teleportationrange` | -0.3 | -0.5 | ADDITION | `8c15c7dd-9ea5-4d86-a4ae-b4d10a7a7b36` |
| `teleportationcd` | ×1.5 | ×2 | MULTIPLY_BASE | `7c9687e5-912e-42e5-a473-c2ada8758c36` |

> 顺风/逆风互斥：施加一方时移除另一方。两者的 `removeAttributeModifiers`（Pr1 变体）分别移除对应 UUID 的修饰符。
>
> **属性名映射**：原作 `teleportationrange` / `teleportationcd` 在重写项目中已更名为 `blink_range` / `blink_cd`（`ModAttributes.BLINK_RANGE` / `BLINK_CD`）。搬运时属性目标需改指这两个新注册项。

### 1.4 风力（amplifier 来源）

效果的 amplifier = `(int)(0 + player_tailwind_force)` 或 `(int)(0 + player_deadwind_force)`，即玩家持久化 NBT 里的 `player_tailwind_force` / `player_deadwind_force`（缺省 0）。

这两个值由**纸飞机 `paper_plane`** 饰品控制（增大风向影响）：

- `PaperPlaneItem.onEquip` → `PaperPlanePr0Procedure`：`putDouble("player_tailwind_force", 1)` + `putDouble("player_deadwind_force", 1)`
- `PaperPlaneItem.onUnequip` → `PaperPlanePr1Procedure`：二者归 0

即：佩戴纸飞机时 amplifier 提升到 1（顺风/逆风都更强）。

## 二、原作文件清单（需搬运）

### 2.1 游戏规则

`PasterdreamModGameRules.PASTERDREAM_WIND_DIRECTION`：
```java
GameRules.register("pasterdreamWindDirection", GameRules.Category.MISC, GameRules.IntegerValue.create(0));
```

### 2.2 世界 tick：换向 + 播报（`WindDirectionPr0Procedure`）

逻辑（仅在 `wind_journey_world` 维度执行）：
1. `dayTime % 24000 == 0`（每昼夜开始）→ `Mth.nextInt(random, 0, 7)` 写入 gamerule；随后 `queueServerWork(2, ...)` 按值 0~7 向全体玩家发送对应风向文案（斜体灰字「朝阳升起... 呼啸的风正吹往 XX方」+ 绿色方向名）。
2. 同 tick 立即对每个玩家：播放 `wind_chime` 音效 + `FEATHER_WHITE_PARTICLE` 粒子（48 个，`y+2`，范围 3，速度 0.05）。
3. `queueServerWork(79, ...)`：再播放 `breeze_wind` 音效。
4. `dayTime == 1` 与 `dayTime == 5`：各再发一次羽毛粒子。

### 2.3 玩家 tick：顺风判定（`WindDirectionPr1Procedure`）

仅在 `wind_journey_world` 维度执行；按当前 gamerule 值查 §1.2 表，若玩家 yaw 落在对应「顺风区间」，则 `addEffect(TAILWIND_BUFF, 20 ticks, amplifier=player_tailwind_force)`。

### 2.4 玩家 tick：逆风判定 + 旗帜反转（`WindDirectionPr2Procedure`）

仅在 `wind_journey_world` 维度执行；按当前 gamerule 值查 §1.2 表「逆风区间」，若玩家 yaw 落在其中：
- **佩戴风骑士旗帜**（`CuriosApi.findEquippedCurio(WIND_KNIGHT_FLAG)`）→ 施加 `TAILWIND_BUFF`（把逆风当顺风）
- **未佩戴** → 施加 `DEADWIND_BUFF`

> ⚠️ 原作判断代码有 MCreator 运算符优先级怪癖：`entity instanceof LivingEntity lv ? findEquippedCurio(...).isPresent() : false == false` 实际等价于 `entity instanceof LivingEntity lv ? isPresent() : true`。搬运时直接写清晰的条件即可。

### 2.5 风向标（`WindVaneItem` + `WindVanePr0Procedure`）

物品 `wind_vane`（`stacksTo(64)`，COMMON），右键：
1. 发送「角度：X 方向：Y」（玩家 pitch / yaw，`##.##` 格式，action bar）
2. 播放 `ding_0` 音效
3. 按 gamerule 值 0~7 发送「当前风向：XX风」

Tooltip：「检测当前的风向与玩家的角度」。

### 2.6 进入维度播报（`WindJourneyWorldPr0Procedure`）

`WindJourneyWorldDimension.onPlayerChangedDimensionEvent` 在玩家进入 `wind_journey_world` 时触发：
- 发送红色文案「本主题梦境尚未完工」
- 播放 `wind_journey` 音乐（MUSIC 通道）

> 重写项目 `WindJourneyDimension` 目前**只有**客户端天空/雾特效，缺少这个 `PlayerChangedDimensionEvent` 监听。

### 2.7 tick 钩子（MCreator 风格，重写需重写为 event）

- `OnWorldTickProcedure`：`TickEvent.LevelTickEvent`（END phase）→ 调 `WindDirectionPr0Procedure`。
- `PlayerTotalTickUpdateProcedure`：`TickEvent.PlayerTickEvent`（END phase）→ 每 `config.PLAYER_TOTAL_TICK_UPDATE` tick 一次，若无防风效果则调 Pr1 + Pr2。

### 2.8 效果与过程（4+4 文件）

| 原作文件 | 作用 |
|---------|------|
| `potion/TailwindBuffMobEffect` | 顺风效果：apply→Pr0（叠属性），remove→Pr1（移除属性）；`isVisibleInGui=false`；`isDurationEffectTick=true` |
| `procedures/TailwindBuffPr0Procedure` | 叠顺风属性（先移除逆风） |
| `procedures/TailwindBuffPr1Procedure` | 移除顺风属性 |
| `potion/DeadwindBuffMobEffect` | 逆风效果（同上结构） |
| `procedures/DeadwindBuffPr0Procedure` | 叠逆风属性（先移除顺风） |
| `procedures/DeadwindBuffPr1Procedure` | 移除逆风属性 |
| `potion/WindproofBuffMobEffect` | 防风标记效果（无属性修正） |

### 2.9 饰品

| 原作文件 | 作用 |
|---------|------|
| `item/WindKnightFlagItem`（`wind_knight_flag`） | 饰品（`ICurioItem`），stacksTo(1)；tooltip「品质：优秀 ★★ / 可以将逆风视为顺风」 |
| `item/PaperPlaneItem`（`paper_plane`） | 饰品，stacksTo(1)；onEquip/onUnequip 设置风力 NBT |

### 2.10 独立机制（可另行排期）

`WindmoorLeavesPr0Procedure`（风泊树叶）：上方为空气时自身变为空气（树叶掉落）。与风向判定无关，属风旅方块随机 tick 行为，可单独搬运。

## 四、搬运方案建议

按重写项目的分层，将 MCreator 的 `procedures` 逻辑内聚为少量类：

### 4.1 注册层

- `ModGameRules` 新增 `WIND_DIRECTION`（`pasterdreamWindDirection`，MISC，默认 0）。
- `ModEffects` 新增 `TAILWIND_BUFF` / `DEADWIND_BUFF` / `WINDPROOF_BUFF` 三项注册。
- `ModItems` 新增 `WIND_VANE` / `WIND_KNIGHT_FLAG` / `PAPER_PLANE` 三项注册。

### 4.2 效果层（`world/effect/`）

- `TailwindBuffEffect` / `DeadwindBuffEffect`：`addAttributeModifiers` / `removeAttributeModifiers` 内直接操作属性（**目标用 `BLINK_RANGE` / `BLINK_CD`**），不再走 Pr0/Pr1 两个 procedure；`initializeClient` 里 `isVisibleInGui=false`。
- `WindproofBuffEffect`：空标记效果。

> 属性修饰仍用固定 UUID，与 §1.3 表一致，避免重复叠加。MOVEMENT_SPEED 用原版 `Attributes.MOVEMENT_SPEED`。

### 4.3 逻辑层（建议 `world/wind/` 或并入 `event/`）

一个内聚的 `WindDirectionHandler`（`@Mod.EventBusSubscriber`）承载：
- `onLevelTick`（`LevelTickEvent`，END，仅 `wind_journey_world`）→ 换向 + 播报 + 音效 + 粒子（原 Pr0）。
- `onPlayerTick`（`PlayerTickEvent`，END，节流 N tick，无防风效果时）→ 顺风判定（原 Pr1）+ 逆风判定/旗帜反转（原 Pr2）。
- 8 方向数据用 `enum` 或常量表表达（方向值 → 中文名 + 顺风 yaw 区间 + 逆风 yaw 区间），消除原作 16 段 `if` 复制粘贴。

### 4.4 物品层

- `world/item/WindVaneItem`：`use()` 里读 gamerule + 发消息 + 放音效（原 WindVanePr0）。
- `world/item/curio/WindKnightFlagItem`、`PaperPlaneItem`：`ICurioItem` 子类；纸飞机 `onEquip`/`onUnequip` 写 `player_tailwind_force` / `player_deadwind_force` NBT。

### 4.5 维度进入播报

`WindJourneyDimension` 增加 `@SubscribeEvent PlayerChangedDimensionEvent`，`event.getTo() == WIND_JOURNEY_WORLD` 时发文案 + `WIND_JOURNEY` 音乐。

### 4.6 可选

- `WindmoorLeavesPr0Procedure` → `world/block/` 下风泊树叶方块的随机 tick 逻辑，单独排期。

## 五、风险与待确认

1. **换向公告文案与物理方向相反**（§1.2 警告）：若想严格还原原作文字，保留「吹往 XX方」原文即可；若想修语义，需把方向名与「吹往」对齐。**建议**：忠实搬运原作文案，行为按 yaw 表，避免引入偏差。
2. **`queueServerWork` 等价物**：原作 `PasterdreamMod.queueServerWork(tick, runnable)` 是延迟调度。重写项目需确认是否已有等价工具（或直接用 `server.getServer().tell(new TickTask(...))` / `scheduler`）。若只想简化，2 tick 后的文案与 79 tick 后的音效可改为同步或并入 tick 计数。
3. **玩家 tick 节流**：原作用 `config.PLAYER_TOTAL_TICK_UPDATE`（配置文件）。重写若不想引入该 config，可硬编码节流间隔（如每 10~20 tick 判定一次）或直接每 tick 判定（效果 20 tick 覆盖）。
4. **属性名迁移**：`teleportationrange/cd → blink_range/cd`。若重写项目另有「传送/闪烁」系统已用 `BLINK_RANGE`/`BLINK_CD`，顺风/逆风对它们的加成/惩罚会**复用同一属性**，需确认数值是否冲突。
5. **纸飞机饰品依赖**：若暂不搬运 `paper_plane`，风力恒为 0（amplifier=0），顺风/逆风仍生效（仅幅度小一档），不影响主机制。可先行搬运核心三件套 + 旗帜 + 风向标，纸飞机按需后补。
6. **`windproof_buff` 来源**：原作中防风效果由何处授予未在本次范围内查清（可能来自其他物品/方块）。搬运时只需注册效果 + 在判定处检查 `hasEffect(WINDPROOF_BUFF)`，授予来源可后续补。
