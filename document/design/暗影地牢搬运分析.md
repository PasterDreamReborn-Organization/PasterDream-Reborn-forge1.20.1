## 二、待搬运项（按推荐顺序）

### 第一步：多方块门系统

> 共 2 组多方块结构，每组由 1 个主方块 + 1 个被动填充方块组成（共 4 个 Block 类），含 3 个 Procedure 逻辑。

#### 2.1.1 方块 ID 映射

| 原作 ID | 原作类名 | 新 ID（提案） | 新类名（提案） | 说明 |
|---------|---------|--------------|--------------|------|
| `shadow_dungeon_door_0` | `ShadowDungeonDoor0Block` | `shadow_dungeon_gate` | `ShadowDungeonGateBlock` | 横向主门，3×3(XZ)，碰撞箱 y=7~9，基岩硬度。onPlace 填充8格 shell，onDestroyed 连带销毁9格，use 检查钥匙 |
| `shadow_dungeon_door_1` | `ShadowDungeonDoor1Block` | `shadow_dungeon_gate_shell` | `ShadowDungeonGateShellBlock` | 横向被动填充方块，同碰撞箱，无交互，不显示在创造物品栏 |
| `shadowdungeondoor_2` | `Shadowdungeondoor2Block` | `shadow_dungeon_barrier` | `ShadowDungeonBarrierBlock` | 纵向主门，3×3(XY)，碰撞箱 z=4~12 全高，基岩硬度。onPlace 填充8格 shell，onDestroyed 连带销毁9格，use 检查进度 |

#### 2.1.2 Procedure 逻辑（3个，集成到主方块类中）

| 原作 Procedure | 触发方 | 新项目中处理方式 |
|---------------|--------|----------------|
| `ShadowDungeonDoorPr0Procedure` | 主门 onPlace | 直接在 `ShadowDungeonGateBlock.onPlace` 和 `ShadowDungeonBarrierBlock.onPlace` 中实现：3×3 填充 shell 方块 |

> Procedure 逻辑简单且与方块强耦合，不建议保留独立 Procedure 类，直接写在对应 Block 类的覆写方法中。

## 三、特殊注意事项

### 3.1 TABITEM_1（调试物品）
原作使用 `TABITEM_1` 作为调试工具将传送门设为出口。新项目中该物品尚未搬运：
- 方案A：同样搬运一个调试物品
- 方案B：改用 command 或创造模式交互替代
- **建议方案B**，减少不必要物品

### 3.2 Structure Block Processor
原作 `shadow_dungeon.nbt` 包含 `minecraft:structure_block`，使用 `block_ignore` processor 在世界生成时跳过。需确认新项目是否沿用此机制，还是改用 jigsaw 自动拼接。

### 3.3 依赖的成就（暂不搬运）
- `achievement_shadow_b_0` — 进入暗影地牢的前提成就
- `achievement_shadow_c_0` — 首次进入地牢时颁发
- `achievement_hide_14` — 修复传送门的前提成就
- `achievement_shadow_npc_5` — 打开最终门（Barrier）的前提成就

在相关 Procedure 中暂时移除成就检查或使用临时条件替代。

### 3.4 CD 冷却存储
原作使用 BlockEntity 的 `persistentData` NBT 存储 CD 状态（`cd`/`time`/`exit`/`layer1~5`）。新项目已通过 BlockEntity 的 `saveAdditional`/`load` 进行持久化。

### 3.5 原作命名规范问题
原作的方块注册 ID 存在多处不规范，本项目的 ID 映射表 `document/design/ID映射表.md` 专门记录修正。门方块的原作命名尤其混乱：
- `shadow_dungeon_door_0` / `shadow_dungeon_door_1`（有下划线）
- `shadowdungeondoor_2` / `shadowdungeondoor_3`（无下划线，不同模式）

搬运时必须统一按项目规范重命名。

### 3.6 搬运原则
- 资源文件**随对应方块一起搬运**，不提前批量迁移
- Procedure 逻辑**直接集成到 Block 类中**，不保留独立 Procedure 类文件（原作 MCreator 限制所致，新项目无此限制）
- 填充方块（GateShell / BarrierShell）**不显示在创造物品栏**，仅由主方块自动放置
