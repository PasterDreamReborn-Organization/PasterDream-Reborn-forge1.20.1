# 亚伦柯斯竞技场搬运任务书

> 目标：把「亚伦柯斯之触」BOSS 战的载体——**亚伦柯斯竞技场系统**搬运到重写版。BOSS 双手实体、技能、Boss 条与全部支撑实体/方块（魔法球/符文塔/暗影之手/恐惧喙/漩涡方块）均已就位，本任务书只覆盖**剩余的竞技场系统本体**。
>
> 核心方块两个：`aaroncos_arena_portals`（亚伦柯斯竞技场传送门）、`aaroncos_eye`（亚伦柯斯之眼，原名 `aaroncoshandspawnblock`）。

## 一、已确认决策

| 项 | 决策 |
|----|------|
| 生成方块重命名 | `aaroncoshandspawnblock` → **`aaroncos_eye`**（亚伦柯斯之眼），语义化 snake_case |
| 唱片重命名 | `aaroncos_disc` → **`aaroncos_music_disc`**（遵循 `_disc` → `_music_disc` 规范，参考 `sweetdream_disc`→`sweet_dream_music_disc`） |
| Procedure 处理 | 与暗影地牢/暮影之笼一致——逻辑**直接集成到 Block/TileEntity/Handler**，不保留独立 Procedure 类 |
| 进度门控 | `achievement_shadow_d_0` / `achievement_shadow_e_0` / `achievement_talent_light` / `achievement_talent_shadow` **留占位**，等成就体系就绪后接入 |
| 结构放置 | 竞技场结构 `aaroncos_arena.nbt` 在**玩家进入维度时手动 `placeInWorld`**（不走 datagen structure provider） |

## 五、关键实现细节

### 5.1 生成控制器（亚伦柯斯之眼）战斗时间轴

Pr1 逻辑按 `time0`（每 20tick 自增 1，因为方块 `tick` 以 20tick 调度）推进：

| time0 | 事件 |
|-------|------|
| 50 / 100 / 150 | 各生成 2 只 Terrorbeak（`z±12`） |
| ≥150 后 | `time0` 复位为 0，循环播放 `aaroncos_music` |
| 双手死亡（99 格范围内空） | 放奖励箱（`y-1`）+ 销毁自身 + 授予进度 + 移除暗影窥视 + 倒计时 20s 传送回主世界 + 清理非玩家实体 |

> 原作 `getShape box(1,-2,7,15,18,9)` 碰撞箱很薄（2 格厚竖板），是「眼」的立牌造型，搬运时保留。

### 5.2 奖励箱掉落逻辑

| 条件 | 掉落 |
|------|------|
| 玩家完成 `talent_light` | `brooch_of_white_orchid` + `white_crystal` |
| 玩家完成 `talent_shadow` | `seal_of_the_corrupted` + `shadow_hilt` |
| 固定 | `pure_horror` |

> 开箱后 `animation` 0→1、播放 `shadow_door`、粒子（shadow_stone/end_rod/smoke/dust_0），41t 后销毁自身。奖励箱为一次性。

### 5.3 传送与维度

- 传送门（`entityInside`）与创建物品（`use`）共用同一传送逻辑：检查 `achievement_shadow_d_0` 或创造 → 传送到 `aaroncos_arena_world` 坐标 (0,70,0)，给 SLOW_FALLING 120t，改 ADVENTURE；失败提示「尚未完成前置进度」。
- 进入维度时（`PlayerChangedDimensionEvent` → Pr0）：`players.size()<2` 才放置竞技场结构（防重复），清理 (0,50,0) 半径 99 的非玩家实体，传送 (0,70,0)。
- 战斗结束：倒计时 20s 后传送回**主世界重生点**（玩家重生点，否则世界出生点），改 SURVIVAL，清理竞技场内非玩家实体。

### 5.4 进度占位

| 原版进度 | 触发点 | 占位方案 |
|---------|--------|----------|
| `achievement_shadow_d_0` | 传送门进入前提 | 临时移除检查或用 `true` 放行 |
| `achievement_shadow_e_0` | 战斗完成授予 | 跳过授予，仅走剩余流程 |
| `achievement_talent_light` / `achievement_talent_shadow` | 奖励箱掉落分支 | 临时用占位标记判断（或固定只走固定掉落 `pure_horror`） |

## 七、建议搬运顺序

```
第 1 步：维度 datagen（DimensionType + NoiseSettings + LevelStem + biome）+ AaroncosArenaWorldDimension
第 2 步：转换 aaroncos_arena.nbt（convert_structure.exe 替换方块 ID）
第 3 步：注册 aaroncos_eye 方块 + BlockEntity + 模型/渲染器（纯框架，不含战斗逻辑）
第 4 步：注册 aaroncos_hand_chest 方块 + 容器 BlockEntity + 模型/渲染器（纯框架）
第 5 步：注册 aaroncos_arena_portals 传送门方块 + aaroncos_arena_create 物品 + 唱片物品
第 6 步：集成 5 个 Procedure 逻辑（激活 / 战斗时间轴 / 开箱 / 传送 / 进入维度）
第 7 步：搬运 3 个掉落物品 + 进度占位
第 8 步：datagen 补语言 / 模型 / 创造物品栏
第 9 步：联调（进入竞技场 → 激活 BOSS → 战斗 → 奖励 → 传送回主世界）
```

> 传送门结构 `aaroncos_arena_portals.nbt` 属灯影之下维度的世界生成，不属本任务书搬运范围（第 2 步仅转换 `aaroncos_arena.nbt`）。
